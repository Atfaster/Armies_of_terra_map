# Оптимизация Surface capture — 10.10.2026

Surface capture сохраняет свежие сведения о поверхностных блоках относительно последней установленной общей карты. Раньше он последовательно разбирал оба MCA каждого изменившегося региона, включая неизменившиеся чанки. Основное время уходило на разбор NBT.

Теперь регионы обрабатываются отдельными процессами. Чанки с идентичным содержимым пропускаются до разбора NBT. Для предыдущей общей карты сохраняется индекс записей с контрольной суммой, а для сохранённых оригиналов — индекс хэшей файлов. Повреждённый кэш пересчитывается. Рабочие копии фиксируются перед запуском процессов; проверки свежих данных клиента сохраняются.

Число процессов автоматически рассчитывается как 80% логических процессоров, с округлением вниз и минимумом один. При 16 логических процессорах максимум — 12. Число задач и доступная память могут уменьшить этот максимум: резервируется 20% свободной памяти, а расход одного процесса оценивается консервативно по размеру региона. Это выбор параллелизма, а не поддержание точной загрузки CPU на уровне 80%.

Запускайте прежний ярлык. Для ручного выбора:

```powershell
merge_steel_soil.bat --no-publish --surface-workers 8
```

Для автоматического выбора можно явно указать `--surface-workers auto`. Параметр действует на Surface capture и Surface merge. Последовательные операции, например упаковка ZIP, используют свой обычный режим.

Кэш capture хранится в `%TEMP%\steel-soil-capture-cache`, кэш объединения — в `%TEMP%\steel-soil-surface-cache`, вне Google Drive. Первый запуск создаёт индексы. Изменение алгоритма может потребовать однократного пересчёта кэша объединения.

Лог показывает завершённые регионы, время, свежие записи, пропущенные чанки и использование индекса. Успешные этапы отмечаются зелёным `[OK]`, ошибки — красным `[ERROR]`. При перенаправлении вывода в файл текст сохраняется без цветовых кодов. Ошибка основного скрипта сохраняет ненулевой код завершения в BAT.

## Проверка

На восьми реальных регионах из последнего снимка клиента:

| Режим Surface capture | Время |
| --- | ---: |
| Прежний последовательный алгоритм | 39,055 с |
| Новый, создание индекса, 8 процессов | 13,738 с |
| Новый, готовый индекс, 8 процессов | 9,217 с |

Во всех восьми регионах результирующие MCA совпали с прежним алгоритмом по SHA-256. Пропущено 1470 неизменившихся чанков. Ускорение на этой выборке — примерно 2,8 раза при создании индекса и 4,2 раза с готовым индексом. Это время этапа capture, а не полного обновления карты.

Пройдены 60 тестов, включая сравнение результатов, параллельную обработку фиксированных снимков, повреждённый кэш, выбор процессов, приоритеты данных, архивы и обработку ошибок. Замер сохранён в [surface-capture-benchmark.json](surface-capture-benchmark.json).

## Откат

После остановки объединения восстановите `season_data.py`, `season_surface.py`, `build_season.py` в `scripts/` и `merge_steel_soil.bat` из `backups/before-capture-optimization-20261010-202905/`. Новые вспомогательные модули после этого не используются. Оригиналы исследований и резервные копии карты сохраняются отдельно.
