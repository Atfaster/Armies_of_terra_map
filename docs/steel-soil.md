# TerraFirmaColonies: Steel & Soil

Новый сезон изолирован в `seasons/steel-soil`. Старая карта в корне проекта сохранена.
Версия клиента: JourneyMap 1.20.1-5.10.3-forge. Обмен включает дневную карту
`overworld/day`, сведения о поверхности `overworld/cache` и наблюдения MineColonies
`addon-data/minecolonies/overworld/border.json`.

[Простая инструкция для тиммейтов](team-map.md): закрыть Minecraft, выделить
`overworld` и `addon-data` в папке сервера и отправить ZIP с именем своего ника.
Архивы старого формата `day/` или `overworld/day/` также принимаются.

Дата 02.10.2026 — дата первого снимка проекта, не дата открытия сервера.
Границы мира: X/Z от −12512 до +12512. Настройки — `config.json` сезона.

При добавлении исследований закройте игру на время снимка. Передавайте оригинальные
day-тайлы, а не ранее полученный объединённый архив: у экспортных PNG время сборки,
а не исследования. ZIP можно положить непосредственно в `imports/steel-soil`: скрипт выбирает
только дневную карту, поверхностный кэш и границы колоний.

```powershell

python scripts/build_season.py snapshot-zip teammate-2 "C:\Users\atfas\Downloads\Telegram Desktop\SDFS.zip"
python scripts/build_season.py build --dry-run
python scripts/build_season.py build
```

Снимки сохраняются с SHA-256 в `sources/<игрок>/<снимок>` и не удаляются. Повторный
снимок тех же файлов пропускается. Старые снимки участвуют в сборке, сохраняя покрытие.
Исходный mtime_ns задаёт приоритет непустых пикселей. При одинаковой дате побеждает
источник позже в source_order, затем снимок с большим digest. Время файла — приближение
свежести тайла, не дата каждого пикселя; файл должен сохранять время при передаче.
Для Drive сохранён modified_time; облачная загрузка тоже могла изменить это время.

## Автоматическое обновление своего клиента

### Обзорная подложка BlueMap

`config.background` задаёт неизменяемый источник `background/source.png`, его SHA-256
и границы X/Z от −12512 до +12512. Источник 626×630 содержит примерно 40 блоков
на пиксель. Масштабирование nearest сохраняет исходные цвета и не придумывает деталей.
Тайлы 512×512 строятся непосредственно из маленького растра; вне границ подложка
прозрачная. Полное изображение 25024×25024 в памяти не создаётся.

`config.world_border` задаёт подтверждённую границу мира с теми же координатами.
В JavaScript поля `minY`/`maxY` соответствуют игровой оси Z. Рамка мира и отсечение
сетки используют этот общий конфиг: сетка 16 блоков вблизи, 64 и 512 при отдалении,
с привязкой к координатному нулю. Корневой index.html остаётся шаблоном старого сезона;
актуальные координаты подставляются при сборке нового сезона.

Подложка не включается в `sources` и не имеет временного приоритета. Сначала
объединяются настоящие PNG игроков, затем они накладываются поверх подложки.
`site/explored/` хранит настоящие исследования отдельно от готовых `site/tiles/`;
`exploration.json` считает только настоящие блоки, а `background.json` описывает подложку.
Проверка релиза независимо воспроизводит приоритет RGBA и проверяет весь составной растр.

При следующих обновлениях свой клиент сравнивается с установленной составной картой:
неизменённая подложка не становится исследованием, изменённые пиксели сохраняются
как дельта JourneyMap. Во входящих ZIP совпадающие пиксели подложки отбрасываются;
исходные PNG сохраняются в снимке в `original-day/`, исходный ZIP тоже сохраняется.
PNG в `day/` снимка содержат отфильтрованные исследования. Уже сохранённые снимки
первого импорта не изменяются.

Ограничение PNG: если JourneyMap нарисовал пиксель точно того же RGBA-цвета, что
подложка, по одной картинке это событие нельзя распознать как новое исследование.
Такие пиксели консервативно остаются подложкой; статистика не завышается. Визуальный
цвет при этом тот же. Поведение перерисовки при посещении чанков требует проверки
в установленном Minecraft; автоматические проверки моделируют изменения PNG.

Для проверки в игре после установки посетите ранее неисследованный берег. Детальная
полоса должна сменить крупные пиксели подложки. Закройте Minecraft и запустите обычный
мёрж: новая полоса сохранится поверх подложки и попадёт в архив команды.

Для новых архивов игроков положите исходные ZIP в `imports/steel-soil/` и запустите
`merge_steel_soil.bat`. Он сам найдёт ZIP непосредственно в этой папке, проверит
слой `day/` или `overworld/day/`, сохранит исходники и добавит их в мерж, обновит
клиент и скопирует ZIP в настроенную папку раздачи. Без `--no-publish` также
публикуется сайт с архивом команды. Уже импортированные ZIP пропускаются
по SHA-256. После успешного мержа, обновления клиента, копирования ZIP и,
если она включена, публикации исходные архивы, вошедшие в сборку, переносятся
в `imports/steel-soil/processed/`.
При совпадении имени добавляется SHA-256 суффикс и при необходимости номер;
существующие файлы не перезаписываются. Новые или изменившиеся ZIP, которые не
вошли в сборку, остаются во входящей папке. При ошибке мержа, копирования или
включённой публикации перенос не запускается. `--dry-run` и `--skip-client`
оставляют архивы на месте. В режиме `--no-publish` перенос выполняется после
проверенного копирования ZIP в папку раздачи; без настройки папки архивы остаются
на месте. Папка `processed` повторно не сканируется;
снимки в `seasons/steel-soil/sources` сохраняются и участвуют в следующих сборках.
Объединённый архив команды с INSTALL.txt
в качестве исходника не принимается. Имена файлов используйте постоянные и разные
для каждого игрока, например `ivan.zip`, `alex.zip`: идентификатор источника
автоматически создаётся из имени ZIP (`day.zip` → `zip-day`).

Та же команда из PowerShell: `python scripts/build_season.py build --import-zips`.
Для предварительной проверки: `python scripts/build_season.py build --import-zips --dry-run`.
Проверка включает новые ZIP, но не сохраняет их снимки, конфигурацию и карту.

Запуск: `merge_steel_soil.bat` или `python scripts/build_season.py build`.
Minecraft должен быть закрыт. Путь клиента задаётся в `seasons/steel-soil/client.json`;
этот файл не включается в публичный сайт.

Перед объединением скрипт сравнивает текущие PNG с последней установленной сборкой.
При первой установке сравнение идёт с сохранёнными личными оригиналами. Новые
непрозрачные пиксели и изменения цветов сохраняются отдельным снимком `client-delta`.
Пиксели общей карты, которые не изменились, не получают искусственно новый приоритет.
Изменение одного только времени файла также не считается новым исследованием.

Свежие отличия клиента получают приоритет выше остальных текущих входных файлов.
Это технический приоритет объединения, а не подтверждённое время исследования каждого
пикселя. Перед установкой проверяются сохранение всего покрытия клиента и точное
совпадение каждого свежего пикселя с результатом. SHA-256 и время файлов сравниваются
повторно перед заменой; появление нового тайла тоже прерывает установку.

Резервные копии оригинальных PNG и manifest.json находятся в `client_backups/` сезона.
Каждый PNG заменяется атомарно. Minecraft проверяется перед сборкой, перед заменой и
после установки; держите игру закрытой до завершения скрипта. Ночь, пещеры, настройки
и waypoints не меняются. Многократная установка не превращает общие пиксели в свои новые
исследования. Данные последней установки — `client_state.json`.

Если установка прервана после начала замены, возможен частично обновлённый набор.
Резервная копия сохраняется, состояние отмечается `interrupted`; автоматическая
следующая установка блокируется. Не удаляйте этот журнал: сверяйте текущие тайлы и
резервную копию прежде чем восстанавливать, чтобы сохранить более поздние исследования.

Для завершения прерванной установки с закрытым Minecraft:

```powershell
python scripts/season_client.py recover
python scripts/build_season.py build
```

Восстановление сначала проверяет каждый текущий файл: допускаются только байты
резервной копии либо ожидаемой сборки. При любых других изменениях или новых тайлах
восстановление отказывается заменять файлы. Сохраняется исходная резервная копия и
дополнительная копия состояния перед восстановлением. Параллельные объединения и
восстановления блокируются файловой блокировкой ОС, освобождаемой при выходе процесса.

`build --dry-run` проверяет живой клиент и свежие пиксели без установки и записи снимков.
`build --skip-client` собирает только сохранённые источники: клиент не читается и не
обновляется, Minecraft закрывать не требуется. Для своего клиента после установки
не используйте обычный `snapshot`: нужные изменения автоматически читает `build`.

Актуальный командный архив: `exports/Steel-Soil-JourneyMap-latest.zip`.
После успешного `build` автоматически запускается `scripts/publish_season.ps1`:
сайт и ZIP загружаются одним коммитом, затем проверяется доступный через Pages архив
по размеру и SHA-256. `build --dry-run` ничего не публикует; `build --no-publish`
выполняет локальный мерж и обновление клиента без загрузки на GitHub.
В обоих режимах готовый ZIP копируется в папку из `seasons/steel-soil/delivery.json`:
`C:\Users\atfas\Drive\Games\Minecraft\TerraFirmaColonies map`.
Копирование проверяется по SHA-256 и завершается атомарной заменой целого файла.
Это подтверждение локальной копии; перед объявлением обновления дождитесь
синхронизации Google Drive. `delivery_state.json` сохраняет ID и SHA-256 копии.
Ярлык `Merge map` на рабочем столе запускает `.bat` с `--no-publish`.
Если публикация не удалась, локальная сборка и ZIP сохраняются; повторите только
`powershell -ExecutionPolicy Bypass -File scripts/publish_season.ps1`.

Страница для команды: https://atfaster.github.io/terrafirmacolonies-map/download.html

Постоянный адрес ZIP: https://atfaster.github.io/terrafirmacolonies-map/downloads/Steel-Soil-JourneyMap-latest.zip

Кнопка скачивания есть на веб-карте. На странице загрузки перечислены шаги установки
и необходимость передать свежие личные исследования до замены совпадающих PNG.
`downloads/latest.json` содержит номер сборки, число тайлов, размер и SHA-256 архива.
Кнопка добавляет номер сборки в ссылку для обхода кеша предыдущего ZIP.
Архив использует фиксированные ZIP timestamps: его байты воспроизводимы при тех же
тайлах и инструкции. Данные ZIP и latest.json производны от build_id и исключены
из расчёта самого build_id, но включены в полный SHA-256 отчёт релиза.

`build --dry-run` выполняет всю сборку и проверку ZIP во временном каталоге, но не
сохраняет релиз и не меняет current.json. База SQLite старого сезона не используется.
Повторная сборка одинаковых данных и страницы даёт тот же build_id.

## Результат и просмотр

`current.json` указывает на `builds/<build_id>`:

- `site/` — только публичные файлы сайта;
- `steel-soil-journeymap-<build_id>.zip` — тайлы и инструкция установки;
- `report.json` — источники, пересечения, размеры и SHA-256 сайта.

```powershell
python scripts/local_map_server.py --season steel-soil
```

Открыть http://127.0.0.1:8000. Отдельный `start_steel_soil_map.bat` или ярлык «Steel and Soil - Local map» на рабочем столе запускает сервер и автоматически открывает карту в браузере по умолчанию. Окно сервера оставляйте открытым; для остановки нажмите Ctrl+C или закройте окно.
Для проверки публичного интерфейса локально: http://127.0.0.1:8000/?view=public.
Локальный редактор сохраняет города и географию в `seasons/steel-soil/data`, не в
старую карту и не в сохранённый релиз. После редактирования снова выполнить build.
Библиотеки Leaflet 1.9.4 и Geoman Free 2.18.3 включены в `vendor/` с лицензиями.
Локальный сайт не требует CDN или подключения к интернету.

Для отката локальной сборки замените build_id и site в current.json на предыдущий
существующий релиз. Исходники и предыдущие сборки сохраняются.

## Поверхностные блоки и колонии

`scripts/season_data.py` читает NBT JourneyMap и собирает файлы регионов по
координатам колонок X/Z, сохраняя типы тегов. Неизменные записи источника не
повышают приоритет при повторной передаче. Подложка не создаёт данных о блоках.
Если пиксель исходного снимка отличается от итоговой карты, запись о блоке
исключается из установки и веб-подсказки; исходник остаётся в истории.
Нулевая длина MCA допустима как пустой кэш. При импорте архива исправные чанки сохраняются,
а повреждённые и неподдерживаемые внешние чанки пропускаются с перечнем в
`manifest.json` и `import-report.json` (`salvaged_chunks`). Исходный ZIP сохраняется;
исходные повреждённые MCA дополнительно сохраняются в `original-extra`.
Повреждение заголовка всего региона по-прежнему останавливает импорт.

`extra_client_state.json` хранит установленную версию кэша и границ. Изменения
проверяются независимо от PNG: замена блока на блок того же цвета тоже учитывается.
Первое чтение сохраняет имеющиеся сведения, следующие — изменения относительно
последней установки. Резервные копии: `client_backups/extra-*`.
После сбоя установки с закрытой игрой выполнить:

```powershell
python scripts/season_data.py recover
```

MineColonies сохраняет частичные наблюдения по чанкам. Новый источник дополняет
сведения; изменения того же источника могут освобождать ранее известные ему чанки.
Для клиента учитываются изменения относительно установленной общей версии.
Отсутствие целой колонии не считается удалением: это может быть изменение видимости.
Колонии различаются по измерению и ID; сайт показывает Overworld.

Сайт содержит `surface/index.json`, сжатые региональные данные `surface/*.json.gz`,
переводы `surface/labels.json` и `colonies.json`. Браузер загружает нужный регион
512×512 и держит до шести регионов в памяти. Границы — отдельный отключаемый слой.
`seasons/steel-soil/team-data.js` подключается только к новому сезону.
Переводы блоков/биомов из сборки сохранены в `surface-labels.json`; без перевода
показывается ID.

Собранные MCA и совместимый `border.json` находятся в `team-data/` релиза и
включаются в командный ZIP. В сайт отдельно публикуются компактные сведения
для браузера. Исходники игроков и локальные пути не публикуются.


## Проверка структуры архивов

Анализатор `scripts/season_archive.py` поддерживает папки `overworld` + `addon-data`,
сокращённый набор `day` + `cache` + `border.json`, отдельные файлы в корне ZIP и
дополнительные внешние папки, например `JourneyMap/mp/Steel~Soil/…`.
Он выбирает один мир, исключает ночь, биомы, рельеф, пещеры и другие измерения.
Архивы нескольких миров и противоречащие друг другу копии выбранных файлов
останавливают импорт. Одинаковые копии пропускаются. PNG и NBT проверяются
до сохранения снимка. Отчёт `import-report.json` лежит рядом с `manifest.json`;
он перечисляет выбранные пути, объёмы, пропуски и отсутствующие виды данных.
Старые архивы, ранее импортированные только как PNG, автоматически проверяются
повторно новым анализатором, если в них есть кэш или границы.

Проверить структуру без импорта:

```powershell
python scripts/season_archive.py imports/steel-soil/имя.zip
```

Если командный ZIP вырастет до 95 MB, он автоматически публикуется как файл
GitHub Release того же репозитория. Сайт остаётся на GitHub Pages; кнопка на странице
загрузки берёт актуальный адрес из `downloads/latest.json`. Небольшие ZIP, как раньше,
лежат непосредственно в сайте. Проверка публикации сверяет полный SHA-256 архива
в обоих случаях. При неудаче публикации исходный архив остаётся в inbox.

## Скорость объединения данных блоков

Число процессов для Surface capture и Surface merge автоматически выбирается по 80% логических процессоров с ограничением по доступной памяти. Неизменившиеся
результаты повторно используются из проверяемого кэша вне Google Drive.
Запуск через `merge_steel_soil.bat` остаётся прежним. Параметр
`--surface-workers 8` задаёт число процессов, а `--rebuild-surface` принудительно
пересчитывает регионы. План, устройство кэша и откат описаны в
[surface-merge-performance.md](surface-merge-performance.md).
